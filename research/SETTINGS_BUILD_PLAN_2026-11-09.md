## Decisions (Claude; Tj can veto)
1. **Toolkit: our own row views on the platform theme, NOT androidx.preference.** The AOSP row/heading/divider/switch rules are in A sec. 1 and C sec. 0 (padding 16 dp, icon frame 56 dp, title 16 sp over summary 14 sp, min height 48 dp, dividers only where the AOSP page has them). A hand-built row is exact by construction, easy to measure, and has no preference-theme / divider-decoration magic that nobody can read here (the androidx layouts are absent from the checkout). Pages = `ScrollView` + `LinearLayout` of rows built in Java from one `SsRows` factory; dp -> px with the real density.
2. **Theme: `parent="@android:style/Theme.DeviceDefault.Settings"`** (public API since 21: solid toolbar, light status bar, white nav bar, DeviceDefault switch / dialogs / seekbar) + the three Settings-only attributes set by hand (`listPreferredItemHeight` 72dip, `homeAsUpIndicator` = a copy of AOSP `ic_arrow_back`, `actionBarStyle` content inset). Sub-pages use the 72 dp title inset (A sec. 1).
3. **Entry:** an `activity-alias` (label "Settings", real Settings icon) with the LAUNCHER filter; its class name in `AppVisibility.ALWAYS_SHOWN_OWN_COMPONENTS`; ENABLED only in custom mode and only while the switch `settings_spoof` is on (release default ON when the build is finished, WIP builds default OFF so a release made mid-way is harmless); flipped by `PackageManager.setComponentEnabledSetting(..., DONT_KILL_APP)` level-triggered (process start + `Mode.set`), OFF the unlock path. The real `com.android.settings` stays out of the custom drawer. Recents: task label "Settings" + the real icon through `TaskDescription`; never swept (own package).
4. **Pages inside ONE activity class `SsPageActivity`** (extra = page id; `SsPage` enum), each page = a builder class `SsPageBattery` ... with `build(ctx, container)` and `onResume()` refresh (ContentObservers / receivers registered in `onStart`, removed in `onStop`).
5. **Pure rules in plain classes with JVM tests** (the repo pattern: final class, private constructor, static methods): `SsBrightness` (HLG gamma % <-> raw 10..255), `SsFormat` (durations, "x ago", sizes in the three AOSP formats), `SsTimeouts`, `SsFontScale`, `SsDensity` (144/170/198/226/254 table), `SsStorage` (the seven rows), `SsBatteryText`. Anything that touches the system goes through one small interface per area so the pure part stays testable.
6. **Permissions:** the app already holds WRITE_SECURE_SETTINGS (adb grant) on the tablet; with it SettingsProvider skips the WRITE_SETTINGS appop for `Settings.System` writes. Without either, a control says plainly "Allow modifying system settings" (the system's `ACTION_MANAGE_WRITE_SETTINGS` page) and shows the current value read-only. Never a crash.
7. **WIP safety:** nothing of this is reachable while `settings_spoof` is OFF; the switch defaults OFF until BN1g (gate) is green, then ON for release builds (debug OFF like `clean_start`, the scenario section `ss` turns it on explicitly).
