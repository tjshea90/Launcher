# BR2: can the pencil in the notification panel be REMOVED (not covered), with accessibility or adb? (Tj, 2026-11-10 19:27 UTC)

Verdict in one line: **no safe way found.** One lever really removes it (the retail-demo flag) but it removes the gear too and was retired for safety; one lever (a resource overlay) is possible on paper, big, and can crash SystemUI; accessibility can only cover.

What is VERIFIED and what is not is marked on every line. Sources read this session: AOSP `android10-release` on the GitHub mirror (QSFooterImpl.java, qs_footer_impl.xml, strings.xml, SettingsButton.java, OverlayManagerService.java, OverlayManagerServiceImpl.java, Shell's AndroidManifest.xml). The retail-demo service source (`RetailDemoModeService.java`) could NOT be fetched: 404 on `android10-release` and on the tag `android-10.0.0_r47`, under `services/core/...` and `services/retaildemo/...`, on GitHub and on googlesource. Everything about what that service does is therefore still the repo's old audit, not a fresh reading.

## How the pencil is drawn (verified, AOSP 10)
- `qs_footer_impl.xml`: the pencil is `@android:id/edit` (an `AlphaOptimizedImageView`, src `@*android:drawable/ic_mode_edit`, description "Edit order of settings.") inside `qs_footer_actions_edit_container`, at the LEFT end of the footer row. The gear is at the right end.
- `QSFooterImpl.updateVisibilities()`: `mEditContainer.setVisibility(isDemo || !mExpanded ? INVISIBLE : VISIBLE)` and the same for `mSettingsButton`. `isDemo = UserManager.isDeviceInDemoMode(mContext)` (reads `Settings.Global.device_demo_mode`). Nothing else decides it: no user setting, no policy, no config resource. `mQsDisabled` (quick settings disabled by `DISABLE2_QUICK_SETTINGS`) hides only the gear container; the whole panel is disabled in that case anyway.

## Levers, one by one
| # | Lever | What it does | Verdict |
| :- | :- | :- | :- |
| 1 | `settings put global device_demo_mode 1` (adb, or the app with `WRITE_SECURE_SETTINGS`) | The only native switch. **Pencil AND gear disappear** at once, nothing to cover (measured on the CI emulator, run 55; consistent with `updateVisibilities` above). | **Rejected.** (a) The gear goes too, so BR1 (gear opens the look-alike) cannot work and the panel would have no way to Settings at all. (b) Android's retail-demo service reacts to this flag (AOSP's retail-mode documentation: it creates a demo user and switches to it when user 0 starts, i.e. at boot). Nobody ever tested a reboot with it on a tablet, and the way out of a surprise demo user can be a factory reset. Retired on 2026-11-05 (safety audit AB1: "it is important that this project doesn't break anything or require me to factory reset my tablet"); the launcher only cleans it up (`DemoModeProfile`). The emulator could measure what a reboot does, but an emulator result cannot prove an OEM tablet safe, so the answer would stay no. |
| 2 | Disable quick settings (`StatusBarManager.disable2(DISABLE2_QUICK_SETTINGS)`) | Hides the whole quick-settings panel. | Rejected: the panel is what Tj uses; the call needs the signature permission `STATUS_BAR`, not available to the app or (for this flag) to a plain adb command on Android 10 (not verified). |
| 3 | Runtime resource overlay (RRO) enabled by adb: `adb install overlay.apk`, `adb shell cmd overlay enable` | Replace the footer layout (`layout/qs_footer_impl.xml` of `com.android.systemui`) with one where the pencil has `visibility="gone"`, or make `ic_mode_edit` transparent. | **Possible on paper, not recommended, nothing built.** Verified: the Android 10 shell holds `CHANGE_OVERLAY_PACKAGES`, and `OverlayManagerService.setEnabled` / `OverlayManagerServiceImpl` contain no signature or overlayable-policy check (those would be in the idmap code, not read). NOT verified: whether idmap creation accepts a user-installed overlay for SystemUI on this ROM. Costs and risks: a second APK that has to be compiled against SystemUI's own resources (the layout uses SystemUI dimens and classes), installed over adb, and re-applied after a reset; a layout mistake crashes SystemUI in a loop (no status bar, no lock screen); replacing the framework drawable instead changes every app that uses `ic_mode_edit` and leaves an invisible pencil that still opens the editor when tapped. Could be tried first on the CI emulator, but it is a project of its own and against the "never risk a factory reset" rule. |
| 4 | Accessibility (what the launcher uses) | Can read nodes, click them and draw windows over other apps. It has **no action that hides, removes or resizes another app's view**. | Covering is the ceiling. Today: an opaque white window over the pencil (`TjPencilCover`). Its only problem was timing (the white box when the panel slides away), fixed in v0.9.2 and not yet confirmed on the tablet (BQ1b). |
| 5 | Other adb tools: `wm size` / `wm density`, `cmd statusbar` (collapse, expand-settings, tiles), SystemUI demo mode (`sysui_demo_allowed` + the `com.android.systemui.demo` broadcast), `settings put secure sysui_qs_tiles` | Change layout size, open or close the panel, rearrange tiles, fake status-bar content. | Nothing found that touches the footer. (The demo-mode broadcast is the status-bar "screenshot mode"; from memory of the Android 10 source, not re-read, it has no command for the quick-settings footer.) |

## What to do instead
- Keep the cover. Wait for Tj's tablet report on the v0.9.2 white-box fix (BQ1b).
- If Tj later wants it truly gone, the only candidate is lever 3, to be tried FIRST on the CI emulator (a small overlay APK built against the emulator's SystemUI, enabled with `cmd overlay`, a crash-loop recovery step written down before it is ever sent to the tablet). Ask first; it is a separate project.
- BR1 (the gear opens the look-alike) is compatible with the cover and with every lever except 1 (which removes the gear).
