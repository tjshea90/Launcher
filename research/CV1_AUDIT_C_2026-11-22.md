# CV1 audit C: app filtering, reload mechanics, port gaps (read-only subagent, HEAD be84f62e, 2026-11-22)

## 1. How the custom launcher decides which apps appear
- The rule is pure code: `app/src/main/java/com/tj/launcher/AppVisibility.java:26-30`. An app shows only if its package is in the stored "allowed" set. Our own package is never shown, except components in `ALWAYS_SHOWN_OWN_COMPONENTS` (only the `SettingsAlias`, `AppVisibility.java:15`, `:28`).
- Storage and glue: `HiddenApps.java`: prefs `tj_apps`, keys `allowed`, `baseline_done`, `auto_done` (`:13-17`). `isShown(Context, ComponentName)` `:74-82`, `isPackageShown(Context, String)` `:84-89`, both true on any exception (fail-open), both first ask `SettingsSpoof.hidesRealSettings` (`:76`, `:86`). `setShown` `:91-99`.
- The mode does not enter the filter, except through the look-alike rule. The subset applies whenever the Launcher3 model loads.

**Where it is applied**
- Model-load gate `AppFilter.shouldShowApp` (`launcher3/src/com/android/launcher3/AppFilter.java:18-21`), called only from `AllAppsList.add` (`AllAppsList.java:76-80`). Drawer, search, package-added / package-updated all go through that one `add`.
- `SessionCommitReceiver.queueAppIconAddition` skips apps that are not shown, so no home icon is auto-added (`SessionCommitReceiver.java:80`).
- `AllAppsList.addPromiseApp` gated at `:94` is dead code (`LAUNCHER3_PROMISE_APPS_IN_ALL_APPS = false`, `BaseFlags.java:67`).
- Drawer search reads the model list as-is (`AlphabeticalAppsList.onAppsUpdated` `:248-251`); `bindAllApps` copies `mBgAllAppsList.data` (`BaseLoaderResults.java:280-285`).

**Surfaces that are NOT filtered**
- **Home and folders:** `LoaderTask.loadWorkspace` reads launcher.db and only checks the target package is enabled (`LoaderTask.java:383-410`). No `HiddenApps` call. By code, a shortcut on the home screen or in a folder stays when its app is hidden.
- Widget picker: the Go `WidgetsModel.getWidgetsList` returns an empty list (`launcher3/go/src/.../WidgetsModel.java:46`).
- Long-press deep shortcuts: `loadDeepShortcuts` loads all (`LoaderTask.java:840-852`); a popup only appears from a visible icon.

**Recents:** `RecentsSweep.plan` removes tasks whose package is not in the drawer per `HiddenApps.isPackageShown` (`RecentsSweep.java:77-97`; Membership `:185`). Without the shell helper `RecentsFilter.blockedNow` classifies by label (`RecentsFilter.java:202`). `TjAccessibilityService.noteHiddenForSweep` (`:2412`) and `NotifSightings.record` (`:138`) also ask `isPackageShown`. `RecentsPolicy` only adds EXCLUDE_FROM_RECENTS for apps launched from the custom home (`RecentsPolicy.java:13-41`), default OFF.

**The Hidden apps chooser:** `HiddenAppsActivity` is not exported, finishes at once if `Mode.isCustom` (`:52`), lists every launchable package except our own (`:55-61`), switch per row; each tap calls `setShown` then `reloadLauncher` (`:113-121`); "Show all" / "Hide all" call `setAll` (`:39-46`, `:79-83`), one reload. Reached through Launcher control's row "Choose the apps shown in the custom launcher" (`tools/emulator_scenario.sh:4787`).

**Special apps**
- Launcher control and Back to custom: own-package LAUNCHER activities (`AndroidManifest.xml:259-285`). `AppVisibility.isShown` hides them in the custom drawer. Both show in the stock drawer.
- Settings look-alike: an `activity-alias`, disabled by default (`AndroidManifest.xml:328-339`). `SettingsSpoof.syncNow` enables it only when `aliasWanted = switchOn && customMode` (`SettingsSpoof.java:48`, `:167-185`). Real `com.android.settings` is hidden exactly while the alias is wanted (`:51-53`, `:63-66`). Home shortcuts to the alias survive the alias flipping off (`LoaderTask.java:395`, `PackageUpdatedTask.java:172`). Release default ON, debug OFF (`SettingsSpoof.java:43`).
- Eleven (`org.lineageos.eleven`): own APK, in `AUTO_ALLOWED_PACKAGES` (`AppVisibility.java:46`); allowed once per install keyed to `firstInstallTime` (`HiddenApps.java:65-72`, `AppVisibility.asked` `:71`); a hand-hide sticks (`handSet`, `:78`); no auto home icon (`AppVisibility.java:106`, `SessionCommitReceiver.java:82`).
- PhoneGuide (`com.tj.phoneguide`) is meant for Tj's phone (`HANDOFF.md:24`); nothing in app/ or launcher3/ mentions it.

**Apps installed after the baseline:** the baseline is lazy; the first ask writes "every installed launchable package minus ours" (`HiddenApps.java:32-40`, `AppVisibility.baseline` `:20`). After that an app not in `allowed` is hidden (`AppVisibility.java:29`); the chooser says "Newly installed apps start OFF" (`HiddenAppsActivity.java:36`). Uninstalling forgets the mark (`PackageUpdatedTask.java:127` -> `HiddenApps.onRemoved` `:101-110`).

## 2. Reload mechanics
- The filter runs at model-load time, not view time. `AllAppsList.add` decides at `AllAppsList.java:77`. `AllAppsList.updatePackage` never re-applies the filter to an entry already in `data` (research/CG1B_LAUNCHER3_PERF_2026-11-17.md, G1). A filter-input change needs a reload or a hand-written model task.
- `HiddenApps.reloadLauncher` (`HiddenApps.java:113-116`) calls `LauncherAppState.getInstance(c).getModel().forceReload()`. `forceReload` (`LauncherModel.java:309-334`): stop the loader, `mModelLoaded=false`, `startLoader` only if a Launcher activity is attached; otherwise the next Launcher start loads. It is a COMPLETE `LoaderTask` (`LoaderTask.java:166-230`): workspace load and bind, all apps, icon-cache update, deep shortcuts, widgets. `getInstance` can construct the whole app state even in a Quickstep-only process (CG1B finding G8).
- Reload callers: every chooser tap and Show all / Hide all (`HiddenAppsActivity.java:45`, `:119`), and `SettingsSpoof.postReload` (`SettingsSpoof.java:105`).
- Package events (`LauncherModel.onPackageAdded/Changed/Removed` `:209-230`, registered `LauncherAppState.java:84`) run `PackageUpdatedTask`; OP_ADD calls `appsList.addPackage` through the filter (`PackageUpdatedTask.java:97-108`).
- `SettingsSpoof` has a cheaper checked reload: starts `SYNC_DELAY_MS = 3000` after a mode change (`:34`); 1200 ms after an alias change (`:108`) a model task runs `reloadNeeded` (`:117-121`); only a wrong model gets the full reload (`:127-165`).
- Reload cost figures are ESTIMATES, none measured on the tablet: "est. 0.3-0.7 s of CPU on the tablet, the home icons blink about 3 s after every return to custom" (`SettingsSpoof.java:111-112`); "est. 0.5-1.5 s of CPU" (`:184`); ~100-200 ms main thread plus ~200-500 ms loader CPU, INFERRED (CG1B G1; "A1, not verified" for the visible blink). Measured startup lines: Application.onCreate 48 ms, process fork to end of it 124 ms (`research/tablet/LATEST.md:33`): not a model load.

## 3. What an "all launchable apps" flag would touch
- Decision points: `HiddenApps.isShown` and `isPackageShown` (`HiddenApps.java:74`, `:84`) and `AppVisibility.isShown` (`:26`). One change reaches every reader: AppFilter, SessionCommitReceiver, the Recents sweep, `RecentsFilter.blockedNow`, `noteHiddenForSweep`, `NotifSightings`. `AppFilter.shouldShowApp` is the single Launcher3 gate.
- Own-package components: `AppVisibility.java:28` and `ALWAYS_SHOWN_OWN_COMPONENTS` decide whether Launcher control and Back to custom would show.
- Settings: `SettingsSpoof.aliasWanted` and `hidesRealSettings` (`:48`, `:51`, `:63`); otherwise the look-alike plus the real Settings (two rows) or neither. Real Settings is also removed from Recents by name through `RecentsFilter` (`:202`) and the `SettingsSpoof.LABEL` special case.
- Model refresh: flipping the flag needs `HiddenApps.reloadLauncher` -> `LauncherModel.forceReload` (`LauncherModel.java:318`), or a hand-written model task like `SettingsSpoof.java:127-165`, plus `AllAppsList` support to re-run the filter.
- Install / removal bookkeeping: `PackageUpdatedTask.java:127` (`onRemoved`) and `SessionCommitReceiver.java:80-82` decide whether apps installed while the flag is on count as "new" when it goes off.
- Recents: the sweep's membership (`RecentsSweep.java:185`) and its callers.
- Chooser: `HiddenAppsActivity` (`:52` mode gate, `:55-63` rows).
- Not filtered, nothing to touch: home items, folders, widget picker, deep shortcuts.

**Layout database**
- Single `launcher.db`: `LauncherFiles.LAUNCHER_DB` (`LauncherFiles.java:17`), in this app's private storage. `LauncherProvider` creates one `DatabaseHelper` (`LauncherProvider.java:158`; constructor `:576-578`).
