## 2. DESIGN v1 (decided 2026-11-08; everything below is Claude's call, Tj only asked for the result)
**Principle: reuse what is proven (real wallpaper screenshot + the Launcher's own pixels), no camera flash per home change, black cover as the fallback so it is never worse than today.**
1. **Picture** = full-screen composite of (a) the PLAIN-WALLPAPER screenshot of the whole display (today decoded and thrown away after the crop: KEEP it as `files/homewall_r<rot>_x<step>.png`, same key and signature as the crop, one extra file per wallpaper step) and (b) the Launcher's full-window `PixelCopy` layer (icons, labels, folders, page dots) taken when the home is idle in front. Stored as ONE composed PNG `files/homecurtain_r<rot>.png` + meta pref `home_curtain_r<rot>` = `signature#step#layerHash#savedAtMs`. Held in memory (ARGB_8888 ~2.4 MB at 600x1024) while the process lives; decoded from disk otherwise.
2. **Refresh** (no flash): after the existing draw-quiet rule on the home, copy the layer; compare a cheap hash of the layer with the stored one; only when it differs (or the wallpaper / rotation / size signature changed) recompose and write (worker thread, tmp then rename, at most once per 30 s). The wallpaper file is the only thing that needs a flash: a missing `homewall` for the current step makes `calDecision` calibrate once (ONE extra flash after the update, same rules and limits as today; say so in the checklist).
3. **Use**: `showResetCover` builds an `ImageView` (the picture, FIT_XY, no scaling surprises: size must equal the real display) when `HomeCurtain.valid(...)` says: switch on, picture for this rotation + signature + display size, not older than a limit, bitmap readable; otherwise the plain black view as today. Same window type, `PixelFormat.OPAQUE`, same failsafe, same hide paths.
4. **Touches (the finding above):** the curtain must CONSUME touches. But NOT before the unlock is confirmed: from the Enter tap until USER_PRESENT keep `NOT_TOUCHABLE` (a wrong PIN must stay retypable: `coverCheck` hides the cover at +1800 ms if still locked); at USER_PRESENT (`applyUnlockChoiceBody`) drop `NOT_TOUCHABLE` with `updateViewLayout` so taps on the picture are swallowed until the real home is in front; hide path unchanged; the 4.5 s failsafe bounds the swallowing. No gesture injection in the reset (it uses accessibility actions): verify before building (`dispatchGesture` grep).
5. **What is shown**: the whole display (nav bar included, it is part of the wallpaper screenshot), never the Quickstep status bar / wifi / apps / notifications.
6. **Switch** `home_curtain`: release default ON, debug default OFF (the `clean_start` / `ScrimMeasure.defaultOn` pattern: older emulator sections must keep seeing the black cover). Launcher control line: "Home curtain: <picture age, WxH, step> / <why none>". Tablet report key `home_curtain`.
7. **Fallbacks (all to black)**: no picture, wrong rotation / size / signature, stale beyond the limit, decode failure, low memory, `addView` of the image view fails.
8. **Open risks**: (a) the page: Launcher3 may or may not return to the default page on the HOME intent: capture the layer when the Launcher is at its CURRENT page and key the picture by `step` too; use the picture whose step equals the wallpaper step the home will show (the last known `wallpaperX`); mismatch = black. (b) icons moved while the process was dead: the hash is only updated while the Launcher runs; the picture can be one edit old. (c) live content (a clock widget) would be frozen: the stock home has none. (d) PixelCopy of a window that was just resumed can return a blank frame: only accept a layer whose alpha is not entirely 0 and equals the previous hash twice.
